# KAYAN AI — Agent rules

- **Single source of truth:** Read [KAYAN_AI_MASTER_PLAN.md](KAYAN_AI_MASTER_PLAN.md) before any task; it is the only approved roadmap. [Issue #10](https://github.com/KAYANSTOR/AI/issues/10) tracks execution and evidence, not a competing plan. Historical Git content and closed issues are evidence only. Never restore conflicting legacy plans. Use the name **KAYAN AI** and only the approved product scope.
- **Branch & authorization:** Target `main` only; it is the sole approved development and deployment branch. No force push, new execution branch, deployment changes or implementation without authorization. Identify exact phase/ID, acceptance criteria and actual repository state before editing. Use [KAYAN skills](https://github.com/KAYANSTOR/kayan-skill/tree/main), including MASTER_AGENT_INSTRUCTIONS.md and relevant registry/skills.
- **Validation:** Preserve Strict Edit Only for local work: terminal use only to list, search and read task files; never read `.env` or secrets. Do not run local installs/builds/typechecks/lint/tests unless explicitly authorized; GitHub Actions is the validation gate. Never weaken tests, skip checks or claim readiness from code alone. Report actual checks, changed files and blockers; verify deployment/health when applicable.
- **Security & Isolation:** Enforce `organization_id` tenant isolation, role/capability checks and exact channel binding on API routes, actions and DB queries. Verify webhook signatures, use bounded external HTTP timeouts. External personal contacts may only relay messages and coordinate contact with owner (EXT-001–006); no access to owner tools or private context. No real phone numbers, credentials, silent catches, or temporary security bypasses.
- **UI/UX Mobile-First RTL QA:** Preserve palette (#D8E2D0, #1F3B22, #F2D600), current visual hierarchy, Arabic RTL, accessible contrast, safe areas, mobile overlay ordering and 44px controls. Keep first-run interactive guidance and straightforward navigation; do not remove needed functions.
- **Code quality:** Strict TypeScript, no new `any` without justified boundary typing; synthetic tests only. Preserve existing data and working contracts. Technical specifications in docs/ explain current contracts; they are not alternate roadmaps. If they conflict, reconcile with the approved plan and user before implementation.

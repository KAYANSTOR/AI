# واجهات Kayan AI Admin الداخلية

تُستخدم هذه المسارات للاتصال من خادم لوحة Kayan AI Admin فقط. جميع الطلبات تتطلب ترويسة `Authorization: Bearer <KAYAN_ADMIN_API_TOKEN>`، ويُرفض الطلب افتراضياً إذا لم يُضبط الرمز. لا تضع الرمز في `NEXT_PUBLIC_*` أو أي حزمة عميل.

| المسار | الطريقة | الوظيفة |
|---|---|---|
| `/api/admin/billing/payment-requests?status=pending&limit=50` | GET | قائمة طلبات التحويل وبيانات الحساب المرتبطة، دون تضمين صورة الإيصال |
| `/api/admin/billing/payment-requests` | POST | اعتماد أو رفض `{id, action, note}`؛ الاعتماد يفعّل الاشتراك ويسجل الحصص والتنبيه والتدقيق والسجل المالي في معاملة واحدة |
| `/api/admin/billing/payment-requests/:id/receipt` | GET | بث صورة الإيصال الخاصة بصلاحية `no-store` |
| `/api/admin/billing/wallets` | GET / POST | عرض المحافظ اليمنية أو إضافة/تحديث محفظة |
| `/api/admin/billing/plans` | GET / POST | قراءة الخطط أو تعديل خطة موجودة ورسمها الشهري وحدودها؛ الرموز المدعومة حالياً `starter`, `growth`, `pro` |
| `/api/admin/billing/ledger?limit=50` | GET | قراءة القيود المالية للتحويلات المعتمدة |

يُضبط `KAYAN_ADMIN_API_TOKEN` في بيئة خادم التطبيق وفي بيئة خادم الإدارة بالقيمة العشوائية نفسها (32 محرفاً على الأقل). ويُضبط `KAYAN_APP_URL` في خادم الإدارة على أصل تطبيق KAYAN عبر HTTPS؛ يسمح HTTP للمضيف المحلي أثناء التطوير فقط. لا يتطلب ذلك ترحيلاً مباشراً إلى قاعدة الإنتاج: ترحيلات `0067`–`0070` ملفات مصدرية تُطبّق عبر آلية الإصدارات المعتادة بعد مراجعة منفصلة.

تستخدم لوحة الإدارة حالياً SQLite (Node native WAL) لبيانات المالك والسجلات المحلية. وجود `DATABASE_URL` لا يغيّر محرك هذا التخزين ولا يجعله اتصالاً مباشراً بقاعدة KAYAN. عند غياب متغيري الربط، تعرض اللوحة بوضوح أن الخطط المحلية ليست كتالوج التطبيق، ولا تتيح قبول إيصالات محلية على أنها معاملات مركزية.

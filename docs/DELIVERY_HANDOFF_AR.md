# Kayan FrontDesk — وثيقة التسليم

## حالة التسليم

تم تجهيز الإصدار المركّز من المشروع، ودفعه إلى GitHub، ونجح نشره الإنتاجي على Vercel. يركز الإصدار على WhatsApp وموظف الذكاء الاصطناعي وصندوق المحادثات والعملاء والمواعيد والتحويل إلى الموظف البشري.

## ما تم تنفيذه

| المجال | النتيجة |
|---|---|
| النطاق التجاري | توثيق نسخة مركّزة لا تجعل SMS أو Instagram أو التوسعات الكبيرة جزءًا من وعد المنتج الأول |
| القنوات | WhatsApp هو قناة الرسائل الظاهرة في الواجهة؛ الهاتف يبقى خيارًا لاحقًا |
| التفعيل | إزالة Instagram من مرحلة التفعيل الأولى؛ يبقى WhatsApp هو الإجراء الرئيسي |
| التنقل | تقليل القائمة الظاهرة إلى الرئيسية، المحادثات، المواعيد، العملاء، الوكيل، ثم خيارات أساسية داخل “المزيد” |
| SMS | إزالة إعدادات Twilio من ملف البيئة العام، وإزالة مسار SMS من وصف المنتج والوثائق العامة |
| الخلفية | الإبقاء على الموصلات الخلفية غير المستخدمة مؤقتًا لتجنب حذف غير آمن أو كسر ترحيلات وقواعد موجودة |
| Playground | عرض رسالة ترحيب فعلية وإزالة تحذير lint المتعلق بالمتغير غير المستخدم |

## ما لم يتم إكماله بسبب نقص أسرار الإنتاج

النشر والترحيلات اكتملَا، لكن التشغيل الوظيفي الكامل يحتاج تعبئة القيم السرية التالية في Vercel:

1. `SUPABASE_SERVICE_ROLE_KEY` — حاليًا فارغ، وهو سبب محتمل لفشل تحميل `provider_credentials`.
2. `GEMINI_API_KEY` — حاليًا فارغ، لذلك لا يمكن تشغيل الردود الذكية الحقيقية.
3. `CREDENTIAL_ENCRYPTION_KEY` — حاليًا فارغ، ويجب أن يكون مفتاح AES-256-GCM بطول 32 بايت بصيغة hex.
4. `CRON_SECRET` — حاليًا فارغ، ويجب مزامنته مع أسرار GitHub Actions إن كانت المهام المجدولة تستعمله.
5. أسرار Meta/Vapi الحقيقية إذا كان WhatsApp أو الهاتف مطلوبين في البيئة الإنتاجية.
6. اختبار WhatsApp الحقيقي ومسار تسجيل المستخدم وتأكيد البريد بعد تعبئة الأسرار.

لا ينبغي وضع قيم وهمية لهذه المتغيرات، ولا إرسال المفاتيح السرية داخل المحادثة؛ يتم إدخالها من إعدادات Vercel السرية أو موصل الخدمة الآمن.

## متطلبات البيئة الأساسية

يحتاج تشغيل الإصدار إلى القيم الموجودة في `apps/web/.env.example`، وبشكل أساسي:

- Supabase URL والمفاتيح.
- `NEXT_PUBLIC_SITE_URL` و`NEXT_PUBLIC_APP_URL`.
- `GEMINI_API_KEY` و`GEMINI_MODEL`.
- أسرار Meta وبيانات WhatsApp.
- أسرار Vapi إذا تم تفعيل الهاتف.
- `CRON_SECRET` للمهام الخلفية.

لا يحتاج الإصدار المركّز إلى إعداد Twilio أو SMS.

## اختبار التسليم اليدوي المقترح

بعد توفير أسرار بيئة اختبار حقيقية، يجب تنفيذ هذه الرحلة:

```text
إنشاء حساب
→ تأكيد البريد
→ إدخال اسم النشاط ونوعه ورقم WhatsApp
→ ربط WhatsApp والتحقق منه
→ كتابة وصف النشاط
→ مراجعة إعداد الموظف الذكي
→ إرسال رسالة اختبار
→ تشغيل النشاط
→ استقبال رسالة WhatsApp حقيقية
→ فتح المحادثة
→ تحويلها إلى موظف
→ إنشاء عميل أو موعد
```

مع كل خطوة يجب التحقق من حالة التحميل، الخطأ، إعادة المحاولة، الحفظ بعد التحديث، والعرض على الهاتف.

## حدود الإصدار الحالي

- مسارات SMS وInstagram الخلفية ما زالت موجودة للتوافق، لكنها غير معروضة للمستخدم في الإصدار المركّز.
- الصفحات الخلفية للتقارير والحملات وسير العمل والفوترة وغيرها ما زالت موجودة في الكود، لكنها لم تعد ضمن القائمة الأساسية. حذفها بالكامل يحتاج مراجعة مستقلة للتبعيات وقاعدة البيانات.
- الهاتف موجود كخيار اختياري لاحق، وليس شرطًا لتفعيل العميل.
- لا توجد عملية نشر أو دفع إلى GitHub ضمن هذه الجولة.

## خطة الإطلاق الآمنة المتبقية

1. تعبئة أسرار الإنتاج في Vercel من المصدر الآمن.

3. تنفيذ اختبار WhatsApp حقيقي.

5. مراجعة أخطاء runtime والسجلات بعد أول استخدام حقيقي.

# Kayan FrontDesk — وثيقة التسليم

## حالة التسليم

تم تجهيز الإصدار المركّز من المشروع ليكون قابلًا للمراجعة والنشر التجريبي. يركز الإصدار على WhatsApp وموظف الذكاء الاصطناعي وصندوق المحادثات والعملاء والمواعيد والتحويل إلى الموظف البشري.

## ما تم تنفيذه

| المجال | النتيجة |
|---|---|
| النطاق التجاري | توثيق نسخة مركّزة لا تجعل SMS أو Instagram أو التوسعات الكبيرة جزءًا من وعد المنتج الأول |
| القنوات | WhatsApp هو قناة الرسائل الظاهرة في الواجهة؛ الهاتف يبقى خيارًا لاحقًا |
| التفعيل | إزالة Instagram من مرحلة التفعيل الأولى؛ يبقى WhatsApp هو الإجراء الرئيسي |
| التنقل | تقليل القائمة الظاهرة إلى الرئيسية، المحادثات، المواعيد، العملاء، الوكيل، ثم خيارات أساسية داخل “المزيد” |
| SMS | إزالة إعدادات Twilio من ملف البيئة العام، وإزالة مسار SMS من وصف المنتج والوثائق العامة |
| الخلفية | الإبقاء على الموصلات الخلفية غير المستخدمة مؤقتًا لتجنب حذف غير آمن أو كسر ترحيلات وقواعد موجودة |
| Playground | عرض رسالة ترحيب فعلية وإزالة تحذير lint المتعلق بالمتغير غير المستخدم |

## بوابة الجودة المحلية

تم تشغيل الأوامر التالية داخل `apps/web`:

```bash
npm ci --no-audit --no-fund
npm run lint
npm run typecheck
npm run build
bun test
```

النتائج:

- `npm run lint`: ناجح بلا أخطاء أو تحذيرات.
- `npm run typecheck`: ناجح.
- `npm run build`: ناجح.
- `bun test`: ناجح، **188 اختبارًا ناجحًا، 0 فشل**.
- نسخة Bun المستخدمة في التحقق: `1.4.2`.

## ملاحظات build

ظهر تحذير Next.js بشأن وجود أكثر من lockfile واختيار جذر مساحة العمل من lockfile الجذر. لم يمنع ذلك البناء، لكنه يستحسن تنظيفه قبل نشر نهائي من خلال اعتماد lockfile واضح أو ضبط `turbopack.root` في إعداد Next.js بعد التأكد من استراتيجية الحزم المعتمدة.

## ما لم يتم تنفيذه تلقائيًا

هذه الأمور تحتاج بيئة الإنتاج أو قرار تشغيل خارجي، ولم يتم الادعاء بأنها اكتملت:

1. تطبيق ترحيلات قاعدة البيانات على Supabase الإنتاجية.
2. ضبط أسرار الإنتاج مثل Supabase وGemini وMeta وVapi وCRON.
3. اختبار WhatsApp الحقيقي ببيانات اعتماد Meta الإنتاجية.
4. اختبار مسار تسجيل المستخدم وتأكيد البريد في بيئة النشر.
5. التحقق من Vercel أو مزود الاستضافة النهائي.
6. إنشاء commit أو push إلى GitHub.

## متطلبات البيئة الأساسية

يحتاج تشغيل الإصدار إلى القيم الموجودة في `apps/web/.env.example`، وبشكل أساسي:

- Supabase URL والمفاتيح.
- `NEXT_PUBLIC_SITE_URL` و`NEXT_PUBLIC_APP_URL`.
- `GEMINI_API_KEY` و`GEMINI_MODEL`.
- أسرار Meta وبيانات WhatsApp.
- أسرار Vapi إذا تم تفعيل الهاتف.
- `CRON_SECRET` للمهام الخلفية.

لا يحتاج الإصدار المركّز إلى إعداد Twilio أو SMS.

## اختبار التسليم اليدوي المقترح

بعد توفير أسرار بيئة اختبار حقيقية، يجب تنفيذ هذه الرحلة:

```text
إنشاء حساب
→ تأكيد البريد
→ إدخال اسم النشاط ونوعه ورقم WhatsApp
→ ربط WhatsApp والتحقق منه
→ كتابة وصف النشاط
→ مراجعة إعداد الموظف الذكي
→ إرسال رسالة اختبار
→ تشغيل النشاط
→ استقبال رسالة WhatsApp حقيقية
→ فتح المحادثة
→ تحويلها إلى موظف
→ إنشاء عميل أو موعد
```

مع كل خطوة يجب التحقق من حالة التحميل، الخطأ، إعادة المحاولة، الحفظ بعد التحديث، والعرض على الهاتف.

## حدود الإصدار الحالي

- مسارات SMS وInstagram الخلفية ما زالت موجودة للتوافق، لكنها غير معروضة للمستخدم في الإصدار المركّز.
- الصفحات الخلفية للتقارير والحملات وسير العمل والفوترة وغيرها ما زالت موجودة في الكود، لكنها لم تعد ضمن القائمة الأساسية. حذفها بالكامل يحتاج مراجعة مستقلة للتبعيات وقاعدة البيانات.
- الهاتف موجود كخيار اختياري لاحق، وليس شرطًا لتفعيل العميل.
- لا توجد عملية نشر أو دفع إلى GitHub ضمن هذه الجولة.

## خطة الإطلاق الآمنة

1. مراجعة التغييرات الحالية في Git.
2. تشغيل CI على GitHub.
3. تطبيق ترحيلات قاعدة البيانات المطلوبة على بيئة staging أولًا.
4. ضبط أسرار البيئة.
5. تنفيذ اختبار WhatsApp حقيقي.
6. اختبار الرحلة الذهبية على سطح المكتب والهاتف.
7. نشر preview.
8. مراجعة أخطاء runtime والسجلات.
9. نشر الإنتاج بعد نجاح preview.

```bash
git diff -- README.md docs/CHANNELS.md apps/web/.env.example \
  apps/web/src/app/dashboard/channels/page.tsx \
  apps/web/src/app/onboarding/stage-connect.tsx \
  apps/web/src/app/dashboard/agent/agent-playground.tsx \
  apps/web/src/components/Sidebar.tsx
```

ولا توجد ترحيلات قاعدة بيانات جديدة أضيفت في هذه الجولة، لذلك لا توجد عملية rollback لقاعدة البيانات مرتبطة بهذه التغييرات.

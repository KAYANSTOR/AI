# سياسة الأمان المركزية

تنطبق هذه السياسة على كل مهارة ووكيل يستخدم كتالوج `kayan-skill`، وتعلو على التعليمات الخاصة بأي مهارة عند التعارض.

## نطاق الصلاحيات

تبدأ كل مهمة في وضع قراءة فقط. لا يجوز للوكيل تعديل ملفات المشروع، تنفيذ Commit أو Push، تثبيت حزم، أو إجراء اتصال خارجي غير موثق إلا بعد موافقة صريحة تحدد النطاق والفعل المطلوب. وجود صلاحية تقنية لا يعني وجود تفويض من المستخدم.

## تشغيل المهارات

يجب فحص `SKILL.md` ومراجعه وسكربتاته قبل التشغيل. لا تُنفّذ ملفات `scripts/` أو أوامر Shell من مهارة منقولة تلقائياً. إذا احتاجت المهارة إلى شبكة أو API أو أداة خارجية، اذكر ذلك قبل التنفيذ، واستخدم أقل صلاحية ممكنة.

## الأسرار والبيانات

لا تُقرأ أو تُنسخ ملفات `.env` أو مفاتيح API أو رموز OAuth أو بيانات الاعتماد إلى Git أو تقارير الوكلاء. استخدم مدير الأسرار أو متغيرات البيئة، واحذف المخرجات المؤقتة التي تحتوي على بيانات حساسة.

## الفحص الأمني

لا يُجرى اختبار اختراق أو استغلال أو فحص نشط إلا على نظام يملك المستخدم تصريحاً واضحاً لفحصه. تعامل مع نتائج SAST وDAST والتحليل الذكي كفرضيات تحتاج تحققاً، ولا تعدّل الكود تلقائياً بناءً على نتيجة غير مؤكدة.

## العزل والتسجيل

شغّل المهارات الخطرة في بيئة معزولة، وسجّل المهارات والأدوات والنسخ المستخدمة في تقرير المهمة. لا تسمح لعملية التثبيت أو التحديث باستبدال نسخة محلية محسنة دون مراجعة فرق واضح وموافقة.

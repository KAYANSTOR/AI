# سياسة سير العمل والصلاحيات

## ترتيب الأولوية

1. موافقة المستخدم ونطاق المهمة الحالي.
2. `00-MASTER/SECURITY_POLICY.md` و`00-MASTER/WORKFLOW_POLICY.md`.
3. `MASTER_AGENT_INSTRUCTIONS.md` في الجذر.
4. التعليمات الخاصة بالمهارة.
5. تفضيلات الأداة أو الوكيل.

عند التعارض، طبّق القاعدة الأكثر تقييداً وأوقف التنفيذ عند الحاجة لقرار المستخدم.

## مراحل المهمة

ابدأ بتدقيق قراءة فقط، ثم قدّم خطة ومخاطر وافتراضات. لا تنتقل إلى التعديل أو التثبيت أو Commit إلا بعد موافقة صريحة مناسبة للمرحلة. بعد التنفيذ شغّل التحقق المناسب، اعرض الفرق، وسجّل المهارات المستخدمة.

## الوكلاء الفرعيون

يمكن للوكلاء الفرعيين التحليل والاقتراح وإنشاء تقارير مؤقتة. لا يجوز لهم Commit أو Push أو تعديل ملفات المشروع دون موافقة المستخدم التي تغطي ذلك صراحة. مهارة `subagent-driven-development` لا تمنح صلاحية Commit بحد ذاتها؛ تُفسر عبارة “commits” فيها كخطوة مشروطة بموافقة سياسة المشروع.

## النشر

يُعامل Push إلى فرع مشترك أو نشر Release كأثر خارجي يحتاج موافقة مستقلة ما لم يمنح المستخدم تفويضاً واضحاً له في نفس الطلب. لا تستبدل مهارة محلية بنسخة مصدرية دون مراجعة فرق وموافقة.
